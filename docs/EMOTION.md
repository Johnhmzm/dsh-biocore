# 情绪

## 机制

情绪是**连续数值**，不是标签。五个维度实时参与，每轮写进上下文：

```
效价 -1…+1   难受 ←→ 舒服
唤醒  0…1    平静 ←→ 激动
支配 -1…+1   被推着 ←→ 握得住
紧张  0…1    松弛 ←→ 绷紧
社交 -1…+1   想退开 ←→ 想靠近
```

这些数值怎么变，有三条路：

```
被一句话推动    模型把话评成维度，按 35% 强度推当前状态（推，不是替换）
随时间自己走    没有消息时也按分钟推进；断 18 小时会累积疲劳与紧张
被经历改写基线  一次难听的对话会挪动慢变量锚点，12 小时后仍然更紧、更少主动
```

## 八个通道

评价不是一个推力，而是八个输出各走各的路：

```
v          效价      → 情绪
a          唤醒      → 情绪
d          支配      → 情绪
stress     压力      → 情绪
social     社交      → 驱力
trust      信任      → 安全感驱力
self_esteem 自尊     → 自我效能
conflict   冲突      → 记录（暂不驱动）
```

这带来的区别很具体：**被骂**会同时压低安全感和社交驱动，**委屈**只压低情绪——
两者效价、压力接近，但受伤的位置不同。

## 你能看到什么

上下文里的一行，例如：

```
此刻：效价-0.15 唤醒0.54 支配+0.00 紧张0.07 社交+0.34。
读法：效价-1难受…+1舒服；唤醒0…1越高越激动；支配-1被推着…+1握得住；
紧张0…1越高越绷；社交-1想退开…+1想靠近
```

不给「开心/难过」这类标签——标签会把连续状态压成几个词，把表达锁死。
读法由解释层给出，模型拿到的是数，怎么落地由它决定。

同时，情绪**决定表达量**：越难受越紧绷，句子越短、语气越软。

## 边界

```
不做情绪识别     不判断用户是什么情绪，只算她自己
不做标签分类     没有离散情绪类别，避免锁死表达
旧记忆无情绪     记忆条目自带 affect，但旧数据没有，情绪一致性召回只对新记忆生效
```
