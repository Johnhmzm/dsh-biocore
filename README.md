# BioCore

给 AI 一个可观测的内部状态：情绪、驱力、疲劳、关系。
模型负责理解与表达，身体负责连续与倾向。

---

## 一、以什么为基础

这不是凭空设计的数值体系，每一层都对应一支已有的理论，并落到具体模块上：

| 层 | 理论来源 | 对应的实现 |
| --- | --- | --- |
| 评价 | Lazarus / Scherer 的评价理论、OCC | `appraisal` `appraisal_action`：7 个评价维度 → 7 个状态增量 |
| 归因 | Weiner (1985) 归因理论 | `attribution` `attributor`：这件事怪谁、能不能改变 |
| 核心情感 | PAD（效价/唤醒/支配） | `v / a / d` 三轴，加四个身体通道 |
| 稳态 | 内感受与稳态调节 | `homeostasis` `regulation_loop`：偏离基线后如何回位 |
| 依恋 | 依恋理论与情绪调节 | `attachment_state` `attachment_regulation`：安全/焦虑/回避如何影响反应 |
| 关系 | Gottman 连接竞标、信任修复 | `connection_bids` `social_repair` `relationship_state` |
| 事件 | Zacks (2007) 事件分割 | `event/segment` `event/segment_adaptive`：按变化点切"事" |
| 记忆激活 | ACT-R (Anderson 2004) | `recall/activation` `event/activation`：新近 × 频率 × 扩散 |
| 记忆双加工 | 熟悉感 / 回想 | 向量召回（熟悉）+ 精排与断言核对（回想） |
| 断言 | 双时态事实 | `event/claims` `event/facts`：谁、什么、何时有效、何时失效 |

**一句话**：把"像人"这件事拆成可计算的部件，每个部件都能指回一篇论文，而不是拍脑袋调参数。

## 二、配合什么，实现什么

### 1. 状态闭环（可用）

```
每轮开始   状态 → 表达倾向 → 注入模型
每轮结束   模型的理解 → 结构化评价 → 写回状态
```

- 注入：`pipeline.inject_block`，按预算裁剪，状态块在前、记忆块在后
- 写回：`pipeline.capture`，评价维度经 `appraisal` 转成状态增量
- 结果：**连续**，不是每轮重置。她会因为上午的事在下午语气发紧。

### 2. 事件与记忆（部分）

```
原句 → 切分成事件 → 抽断言 → 落到状态层
```

- 切分：变化点检测，阈值按会话自适应（不是全局常数）
- 断言：从原句抽出「主体·属性·值」，带有效区间——所以"下周三去医院"到周三之后会自动过期，而不是永久污染
- 召回：向量粗召回 → 精排 → 空间铺开；预算可配（5k 到 40k，实测召回率 76% → 100%）
- 现状：切分与断言模块已在仓库，**部署侧尚未接满**——这是下一步的重点

### 3. 自发性行为（部分）

自发不是随机，是一条链：

```
驱力累积（时间 × 缺口 × 关系权重）
   ↓ 越过阈值
生成"想说的理由"（`autonomy_reason`）
   ↓ 通过门控
发送（冷却 ≥30min、每日 ≤3 条、静默时段）
   ↓ 结果回流
犹豫或更主动（写回关系与驱力）
```

**她自己能生成"为什么想说话"**，而不是等一个定时器把她叫醒。
目前的缺口：门控读的是常数，**还没有读学习到的结果**——所以八点那条消息看起来像闹钟。

### 4. 自主学习（部分）

现有的学习有四处，各自学不同的东西：

```
policy_learning   上下文（时段/沉默相位/依恋）× 动作 → 回报（是否被回、回复间隔）
predictor         下一状态预测 → 误差本身就是"意外"信号
memory_dual       记忆强度与衰减 → 决定什么被记住、什么被忘掉
feedback_memory   用户反馈 → 直接影响关系与倾向
```

判据不是"有没有代码"，而是**有没有被读取**。目前的实情：

| 学习点 | 在学 | 被决策读取 |
| --- | --- | --- |
| 策略表（何时开口） | ✅ | ❌ |
| 预测误差（意外） | ✅ | ⚠️ 部分 |
| 记忆强度 | ✅ | ✅ |
| 反馈记忆 | ✅ | ✅ |

**这张表就是下一阶段的路线图**：不是加新的学习，是把已有的接进门。

### 5. 迭代（部分）

每次互动都会更新四样东西，越靠后越慢：

```
秒级   评价 → 状态增量
分级   关系数值（信任/亲密/冲突）
日级   事件压缩、记忆强度衰减、空间轴权重
周级   人设倾向的微调（尚未实现）
```

慢变量才是"她变了"的来源。目前秒级与分级可用，日级部分可用，周级还没有。

## 三、一天里会发生什么

```
早上   状态偏低，回复变短，不主动开口
中午   你说了件让她在意的事，紧张上升，语气收紧
傍晚   长时间没说话，驱力回升，但她记得上次被冷落后的犹豫
夜里   疲惫压低唤醒，回复回到简短，把这一天压成一个事件
```

这些不是写死的规则，是状态在走。

## 四、安装

**推荐从插件市场安装**：市场会同时写好 `bundles`，装完重启即可用。

命令行安装只把包放进 `node_modules`，还需要自己把包名加进 profile 的 `dsh.profile.bundles`
（见第七节）——否则插件不会报错、也不会出现，`/api/biocore/*` 全部 404。

```bash
dsh plugin --profile web add dsh-biocore   # 等价于 pnpm add，不写 bundles
```

对外访问时启动加两个参数放行域名：

```bash
dsh --profile web --port 3080 \
    --public-url https://your.host:3080/ \
    --trusted-host your.host:3080
```

## 五、现在能做到什么（已实现，附验证方式）

### 身体

| 能力 | 表现 | 怎么验 |
| --- | --- | --- |
| 状态随对话改变 | 被夸效价上升，被骂效价下降、压力升高 | 同一句话正负两种说法，看状态行变化 |
| 无人时自己走 | 没有消息也会随时间推进，压力会累积 | 断 18 小时再说话，压力高于断开前 |
| 经历改变基线 | 一次难听的对话，12 小时后仍更紧张、主动性更低 | 对比挨骂/被夸两条会话 12 小时后的状态 |
| 自发选择 | 静置时会出现「想说话 / 不想说」的分化 | 12 个随机种子静置 200 步，动作不全相同 |
| 情绪影响措辞 | 状态写进提示词，回复长度与语气随之变化 | 开关身体各生成一次回复，长度差约 25% |

### 学习

| 能力 | 表现 | 怎么验 |
| --- | --- | --- |
| 模型判分 | 每条回复由模型打分（接住情绪 / 说教 / 伤人） | `turn_end` 返回 `exchange_grade` |
| 策略学习 | 学会该时段该怎么办，学出「别主动」就不再发 | `policy_q.json` 里 `approach` 的 Q 值随反馈变化 |
| 关联学习 | 蘑菇体把「什么线索预示什么结果」写进权重 | `mindbase_mb.json`，正负训练后预测值分开 |
| 每轮微迭代 | 噪声幅度随适应度微调，一天几轮也能单调改进 | `mindbase_needs.json` 里的 `noise_amp` |

### 记忆

| 能力 | 表现 | 怎么验 |
| --- | --- | --- |
| 按相关性排序 | 注入块顶部是与当前话题相关的内容，而非最早的对话 | 换话题提问，块首内容随之变化 |
| 预算生效 | 配置的 `inject_chars` 真的用满 | 块长度接近配置值 |
| 精排参与 | rerank 把该看的句子提到前 10 | 前 10 命中率 60.9% → 69.4% |
| 情绪一致性 | 高兴时更容易想起高兴的事 | 同一条记忆、两种状态，召回的句子不同 |
| 两套记忆互通 | 主记忆里召回过的句子，果蝇脑也能检索到 | `mindbase_mirror.json` 有记录且可 retrieve |

## 七、手动安装才需要：写进 bundles

编辑 `~/.dsh/profiles/<profile>/package.json`：

```json
{
  "dsh": { "profile": { "bundles": [ "...", "dsh-biocore" ] } },
  "dependencies": { "dsh-biocore": "0.5.12" }
}
```

重启后启动日志出现 `__bioWorker started` 才算加载成功；`/api/biocore/stats` 返回 `200` 即为正常
（`available:false, reason:no_session` 表示还没进会话）。

## 八、发版前必须跑的检查

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\check_release_hygiene.ps1
```

检查密钥、截图（白名单外一律拦下）、数据目录、超大文件；退出码 0 才允许发布。
推送后必须用 `git ls-remote` 的 SHA 与本地 `git rev-parse HEAD` 比对，
**不要相信 `git push` 的输出**——被拒绝时它同样会打印带 `->` 的行。
